# Automatic clipboard optimization

## Data flow

`ClipboardMonitorService` owns a 600 ms async polling task while enabled. It watches `NSPasteboard.general.changeCount`, establishes a baseline at startup/re-enable, and inspects advertised types before reading image content. It skips plain text, web URLs, mixed/multiple items, concealed/transient/autogenerated items, and ignored frontmost bundle IDs. Ignored-app detection is a frontmost-app heuristic, not proof of clipboard authorship. Monitoring and observable state run on MainActor; decoding, hashing, conversion, compression, and file preparation run off MainActor.

The app-lifetime `WatchedFoldersController` admits clipboard operations into its existing sequential pending queue. There is no second compression queue. A newer clipboard change removes an older waiting clipboard operation. Folder pause gates only folder jobs; clipboard pause cancels polling and waiting clipboard work, and invalidates the commit generation for active work. Existing foreground manual conversions are unchanged. MenuBarExtra uses the same active/queued count, session statistics, and recent-result models for clipboard and folder work.

## Formats and originals

Raw PNG, JPEG, TIFF, and HEIC are accepted when ImageIO validates one image. Image files copied in Finder are read through AppKit's NSURL pasteboard APIs for sandbox-aware access. Source files are read only. Copied files produce temporary optimized files, written using NSURL pasteboard writers; raw images remain raw image representations. Multiple Finder selections are left untouched.

PNG/JPEG/HEIC reuse `ImageOptimizationService`. TIFF uses the existing `ImageConversionService` to produce PNG, then the same optimizer. The final output is compared with the original TIFF bytes, even if PNG cannot be reduced further. Transparency is retained. Lossless JPEG/HEIC is skipped because the existing backend cannot provide it. Inputs are limited to 128 MB and 64 million pixels. Outputs are reopened and decoded, dimensions checked, and published only when smaller. Work directories are removed on normal success, failure, and cancellation.

## Clipboard safety

Each job captures a clipboard generation. Before committing, the monitor rechecks generation and enabled/lifecycle state. The writer prepares representations before clearing, rechecks before and after `prepareForNewContents`, and writes without an asynchronous gap. Newer copies observed during processing remain untouched. Explicit Copy/Copy All uses the same guarded writer.

Self-write prevention combines the last written generation, a private marker on raw image items, and SHA256 fingerprints of successful input/output bytes. The registry contains at most 128 entries for one hour and holds hashes only. It is not persistent across launches and cannot recognize every image re-encoded by another application.

NSPasteboard has no documented atomic compare-and-swap. A different process can still write during the final synchronous check/write interval. Failed-write rollback is best effort and restores supported image/file representations only, not every auxiliary HTML/custom representation. No code claims an absolute interprocess atomicity guarantee. Compression failures and no-reduction results never clear the clipboard.

Writes use `.currentHostOnly`; no network request or cloud optimizer is introduced. On systems with pasteboard privacy controls, macOS may require permission. The app does not bypass those controls or request Accessibility, Input Monitoring, or Screen Recording.

## Results and retention

Settings include independent enable switches for pixels and copied files, preset, optional result card, optional collection, and bundle-ID-based ignored applications. A single rectangular nonactivating card shows a downsampled thumbnail, sizes, reduction, dimensions, Copy, Save, Close, and Reveal for file-backed results. A newer card replaces the previous card. Cards do not auto-dismiss or stack.

Collection is memory-only, off by default, capped at 20 results and 128 MB. Copy All writes multiple pasteboard items; receiving apps decide how to paste them. Save/Save All uses a user-selected folder and the existing collision-safe publisher. Clear releases collected image data; clipboard-owned representations remain available for pasting.

File exports have a bounded temporary footprint (64 directories / 256 MB, including concurrent preparation). Exports are reused by result ID, and unused files are reclaimed after clipboard changes or writes. Files referenced by the current clipboard are retained, including at orderly quit, so Finder can still paste them. On later launches, unreferenced UUID export directories older than 24 hours are swept; crash remnants may remain until then. There is no permanent image library. Job shutdown during process termination can leave temporary OS files; this is not secure deletion.

## Verification

Tests use private named pasteboards, generated images, isolated preferences, and temporary folders. The test host never restores personal watched folders or starts the real clipboard monitor. Cases cover type exclusion, SHA256 duplicate prevention, valid-image generation rejection, delayed A/new C copying, no-reduction/failure preservation, PNG pixel/alpha preservation, TIFF/JPEG, unchanged source files, temporary cleanup, ignored apps, independent folder pause, copied-file NSURL round trips, and repeated export reuse.

Manual checks still required on the installed sandboxed app:

1. Copy a screenshot with Control-Shift-Command-4; paste into Preview and a document.
2. Browser Copy Image with transparency; verify visual appearance and paste behavior.
3. Copy a Finder image outside previously granted folders; verify source unchanged and paste the temporary file into another sandboxed app.
4. Copy image A then text B while processing; B must remain.
5. Disable clipboard optimization while folder watching stays active; then test the reverse.
6. Close the main window, exercise ignored apps, Copy All/Save All/Clear, and Quit.

Optimization is asynchronous. Pasting before completion uses the original image. Some destination apps re-encode pasted pixels, so reduced clipboard bytes do not guarantee the same savings in the destination document. macOS 14/Intel and live cross-application permission behavior require separate release verification.
