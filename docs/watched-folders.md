# Watched folders

OrbitConvert watches only folders chosen through Settings > Watched Folders. Adding a folder uses `NSOpenPanel` and saves an app-scoped security bookmark in UserDefaults. On launch, the bookmark is resolved with security scope; a stale bookmark is refreshed. Lost access marks the folder unavailable and offers Grant Access. Monitoring requires the app process to remain running. Menu bar status and optional Launch at Login make that visible.

`FolderWatchService` uses public Core Services FSEvents with file events, `WatchRoot`, and a dispatch queue. Normal file events are handled by path; dropped events and new subdirectories trigger a rescan. Initial scans and rescans run off the main actor. An initial snapshot excludes existing files unless the user selects Optimize Existing Files; the stream replays arrivals during that snapshot. The user can enable/disable folders, pause globally, select a compression preset and supported types, include subfolders, and choose Replace Original, Move Original to Trash, or Keep Both.

Supported watched inputs are JPEG, PNG, HEIC, and PDF. ImageIO handles image optimization; PDFKit handles PDF optimization. HEIC requires the installed ImageIO HEIC encoder. JPEG/HEIC Balanced and Maximum are lossy; PNG re-encoding is lossless. PDFKit's native options do not provide exact target DPI or JPEG quality. One sequential worker limits memory and encoder load. Duplicate paths are queued once; recent output fingerprints and the baseline set prevent the app's replacements and Keep Both outputs from being optimized again.

Before a job, the app ignores hidden, temporary/download, symlink, unsupported, and not-current iCloud files. It checks size, nanosecond modification time, device, and inode for two consecutive one-second intervals, then confirms the file is readable. A job times out after 60 checks and retries up to three times with a delay. The service rechecks that fingerprint before replacement. No filesystem API can prove an arbitrary uncoordinated writer is finished if it pauses longer than the quiet period, so this remains a best-effort stability rule. Test large downloads and exports with the apps that create them before relying on automatic replacement.

Each optimizer writes into a unique private job directory in the app's temporary area. Existing image/PDF services reopen and validate output and discard candidates that are not smaller. `SafeFileReplacementService` copies a valid candidate into a private directory beside the source so the final swap is on the same volume. It checks the original fingerprint again, calls `FileManager.replaceItemAt` with a unique retained backup, validates the result, then removes the backup or sends it to Trash according to policy. If post-swap validation fails, it restores the backup; if restoration fails, it retains the hidden backup and reports its name. Keep Both uses the existing no-overwrite publisher. An app crash during replacement may leave a hidden `.orbitconvert-backup-*` recovery file; do not delete it without inspecting the source.

Settings shows the five most recent results below the folder controls. View All Activity in Settings or the menu bar opens the full saved log, including previous sessions. Each optimized file shows its date/time, original size, final size, amount saved, and percentage reduction; sizes use adaptive file units such as KB and MB. Skipped and failed results retain their explanatory messages. The log combines watched-folder and clipboard jobs; manual foreground conversions are not part of this history. Records never saved cannot be reconstructed.

Activity stores only the latest 200 filenames, outcomes, byte counts, dates, and messages locally. It stores no file contents or analytics. The folder list stores bookmark bytes, not raw paths. FSEvents may coalesce events on network/cloud volumes; signed sandbox behavior still needs manual verification. External volumes must be available when watching; a moved or unmounted folder is marked unavailable. See [sandbox](sandbox-and-output.md) and [testing](testing.md).

## Menu bar status

The existing SwiftUI MenuBarExtra uses window style at 350 points wide. It observes the same MainActor WatchedFoldersController and sequential queue used for automatic optimization. Observable pending and active storage drive the icon count, including queued retry delays. No second queue or polling timer is introduced. The paused icon suppresses the status-bar count; the popup still shows remaining work.

Pause stops new admission and the next queued job. Active optimization finishes safely, including replacement. Accepted waiting jobs remain queued until Resume. FSEvents stays attached while paused; files arriving during pause are not admitted automatically. Use Optimize Existing Files to process those files. Removing or disabling a folder retains the existing cancellation behavior.

Phase updates show checking, compressing, and validating/saving. The safe replacement service validates both before and after swapping; these steps share one truthful phase rather than fabricated percentages. Encoders provide no fractional progress, so active rows use indeterminate progress. Retries contribute statistics only after their final outcome.

Session statistics reset on launch and distinguish optimized, skipped, and failed files. Only optimized results contribute byte totals. Persistent recent history is separate and limited to 200 entries, with three shown in the popup, five in Watched Folders settings, and a separate activity window for the rest. Only filenames appear. A single main Window prevents repeated Open actions from creating duplicates. Closing it leaves MenuBarExtra and watching running; Quit terminates the application.

This menu reports automatic watched-folder optimization. Manual foreground conversions retain their existing progress and results in the main window. Validate menu visibility, reopening, Settings, VoiceOver, and light/dark appearance in an installed app; unit tests cover state calculations and the watcher pipeline, not system menu rendering.

References: [Apple MenuBarExtra](https://developer.apple.com/documentation/swiftui/menubarextra) and [window style](https://developer.apple.com/documentation/swiftui/menubarextrastyle/window).
