# PDF and compression implementation

Status: implemented core actions and native optimization. Existing image conversion remains; both action presentations are rectangular panels.

1. Extend byte-validated intake to PDF. Widen the format-only `FileAction` descriptor to image, PDF, and Compress actions; keep panel rendering separate from service dispatch. Add ordered batch selection for image-to-PDF, PDF merge, and Compress All.
2. Generalize `FileOutputService` naming and extension while keeping its private temporary directory, no-overwrite publication, and source preservation. Add tests before changing the output service.
3. Add PDFKit/Core Graphics services for image-to-PDF, PDF page rendering to JPEG/PNG, page extraction, and merge. Render pages sequentially off the main actor. Validate each output by reopening it before publication.
4. Add JPEG and PNG optimization with ImageIO. JPEG re-encoding is lossy even at high quality; PNG remains lossless unless a future palette optimizer is added. Preserve metadata by default. Discard a candidate that is not smaller.
5. Add native PDFKit optimization. A plain rewrite is a lossless candidate. `saveImagesAsJPEG` and `optimizeImagesForScreen` can reduce image-heavy PDFs without rasterizing whole pages. Apple's [PDFKit session](https://developer.apple.com/videos/play/wwdc2022/10089/) describes those options but does not provide exact target DPI or JPEG-quality controls. Label modes by actual operation; validate page count, extractable text, and file size. Do not claim fixed 180/120 DPI or 0.85/0.70 quality.
6. Added a native Settings scene for compression preset, JPEG export quality, PDF-to-image resolution, and metadata policy. Conversion rows show output sizes and savings. Batch optimization runs one file at a time and reports per-file failures. The original is always kept; replacement and undo are not exposed yet.

PDF input actions: render to JPEG or PNG at 72, 100, 150, 200, or 300 DPI; extract an individual page, range, or all pages without rasterizing; merge PDFs in the displayed selection order. Image input actions include one image to PDF or multiple images to a page-per-image PDF, with fit, image-size, A4, and US Letter layouts. Rendering uses Core Graphics off the main actor and rejects pages exceeding 100 million output pixels. It draws visible PDFKit annotations after the page content. Unusual annotation types and interactive widget states still need manual comparison with Preview.

JPEG optimization uses ImageIO re-encoding at 0.85 for Balanced or 0.70 for Maximum. PNG optimization re-encodes losslessly and never claims palette reduction. ImageIO preserves source metadata by default. The candidate is validated and published only when smaller. PDFKit native Lossless rewrites the document; Balanced applies `saveImagesAsJPEG`; Maximum also applies `optimizeImagesForScreen`. These options do not offer precise DPI or JPEG quality, and PDF optimization rejects such parameters rather than silently ignoring them. A PDF candidate is reopened and checked for page count, extractable text, URL-link count, and top-level outline count before publication. Complex annotations and nested outlines still need broader validation.

Temporary files live in private directories inside the selected output folder and are removed after success, failure, or cancellation. Final names use collision-safe publication. A signed sandbox may require the user to select an output folder when same-folder access is denied. The user original is never overwritten. Batch mode asks for one output folder and continues after per-file errors.

Ghostscript is not bundled. Its [AGPL/commercial license](https://ghostscript.com/faq/) and App Store distribution need a separate decision. If precise PDF downsampling is later required, add one isolated backend with `Process.arguments`, safe executable discovery, output validation, and a distribution review. No shell command strings or automatic tool downloads.

Automated tests cover page count, order, rotation, DPI dimensions, a visible annotation, selectable text through extraction/merge, corrupt PDF rejection, PNG pixel equivalence, collisions, size arithmetic, larger-output skip, partial batch failure, and original preservation. Signed sandbox, complex PDFs, large-file profiling, and manual UI checks remain release gates.
